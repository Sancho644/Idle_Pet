# Idle_Pet — инструкции для Codex

## Источники правил
- Сначала прочитай `docs/decisions.md`, затем релевантные разделы `docs/design/GDD.md`, `docs/technical/TDD.md`, `docs/open-items.md` и `docs/backlog.md`.
- Утверждённые GD-001–010 обязательны. GDD v1.1 заменяет v1.0: офлайн-прогресс без лимитов, смерть вне игры возможна. Не возвращай защитное окно, замедление или лимит отсутствия.
- Соблюдай утверждённые TD-001–006 для T00. Остальные предложения TDD и уведомления требуют отдельного согласования. Уточняй только блокирующие вопросы, остальные фиксируй в open-items.md. Временные значения тестового баланса явно обозначай.

## Рабочий процесс
- Работай небольшими задачами из backlog. Перед изменениями проверь git status и прочитай нужные файлы. Не перезаписывай пользовательские изменения. Не делай commit, push, reset, clean, force push или merge без явного разрешения.
- Unity 6000.6.7f1, URP 17.6.0, Windows и Android. Используй официальный Unity CLI и Pipeline 1.0.1 и навыки Unity Agent Plugin 0.1.10-beta. Не устанавливай сторонний Unity MCP без согласования. Если необходим запуск вне песочницы, запрашивай разрешение; не обходи ограничения. Не запускай второй редактор поверх открытого проекта.
- Для работы с ассетами, сценами, префабами и компонентами предпочитай Unity Editor API через CLI; не редактируй Unity YAML вручную без обоснования. Не меняй GUID существующих ассетов. Сохраняй соответствующие .meta.
- Новые зависимости, изменение версии редактора и render pipeline согласовывай. Установка VContainer отложена до появления Bootstrap. Не добавляй UniTask/Addressables заранее.

## Архитектура
- Domain — чистый C# без UnityEngine, файлового I/O и прямого обращения к системным часам. Application оркестрирует сценарии, Infrastructure реализует порты, Presentation отображает, Bootstrap связывает. Без циклических asmdef-ссылок. Не вводи ECS без отдельного решения.
- Сборки и пространства имён проекта используют `IdlePet.*`. Передавай зависимости через конструктор, когда они нужны для выполнения задачи.
- GameState — единый источник состояния. UI/Animator/NavMesh не владеют правилами ухода. ScriptableObject — конфигурации, не изменяемое состояние сохранения. Стабильные идентификаторы контента.
- Одна симуляция для online/offline/forecast; UTC, внедряемые часы и воспроизводимый RNG. Forecast работает на независимой копии без побочных эффектов. Симулируй весь прошедший интервал; после смерти не создавай автоматически следующее яйцо. Учитывай границы событий, а не каждый кадр отсутствия.
- Разнообразная анатомия: композиция, capabilities и адаптеры движения/анимаций. Mixamo только для совместимых гуманоидов. Не привязывай игровую логику к скелету.
