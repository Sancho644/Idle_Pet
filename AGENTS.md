## Архитектура
- Domain — чистый C# без UnityEngine, файлового I/O и прямого обращения к системным часам. Application оркестрирует сценарии, Infrastructure реализует порты, Presentation отображает, Bootstrap связывает. Без циклических asmdef-ссылок. Не вводи ECS без отдельного решения.
- Сборки и пространства имён проекта используют `IdlePet.*`. Передавай зависимости через конструктор, когда они нужны для выполнения задачи.
- GameState — единый источник состояния. UI/Animator/NavMesh не владеют правилами ухода. ScriptableObject — конфигурации, не изменяемое состояние сохранения. Стабильные идентификаторы контента.
- Используй единое детерминированное событийное ядро для online/offline/forecast. Все три проекции используют логический курсор `long` в миллисекундах. Внешние часы находятся за границей Domain. Соблюдай канонический fixed-point и сохранение остатков по TD-015, границы `(currentTime, targetTime]`, причинную очередь и восстановление по TD-012 и TD-016. Используй независимые сохраняемые потоки PCG32 v1 по TD-017. Forecast работает на глубокой копии состояния и RNG без побочных эффектов.
- Перед валидацией игровой команды продвигай симуляцию до её времени. Отказ команды сохраняет уже обработанное время и естественные события. Отклонённое действие не применяет эффекты и не расходует ресурсы или RNG. Ошибку ядра обрабатывай отдельно по TD-016. [R-04](docs/technical/simulation-engine.md)
- Симулируй весь фактически прошедший офлайн-интервал без лимита, замедления или защитного окна. Смерть вне игры возможна. После смерти жизнь питомца завершается, новое яйцо появляется по действию игрока. Интегрируй между логическими границами и сохраняй точность независимо от разбиения интервала.
- Логическая доступность мебели и состояние источников света определяют результаты ухода. Unity Presentation отображает их. Каждое действие применяет эффекты один раз. Используй единый механизм модификаторов и исключай двойное списание ресурсов или начисление эффектов.
- Разнообразная анатомия: композиция, capabilities и адаптеры движения/анимаций. Mixamo только для совместимых гуманоидов. Не привязывай игровую логику к скелету.

## TD-008 — конфигурации и локализация

- Настраиваемые параметры, тайминги, пороги, вероятности, коэффициенты и определения контента задавай через ScriptableObject-конфигурации и каталоги. В конфигурациях храни ссылки на модели, префабы, звуки, VFX и другие ресурсы. Добавление контента в рамках существующих механик должно обходиться изменением данных.
- Все пользовательские тексты и динамические шаблоны храни в Unity Localization String Tables. Ссылки и ключи задавай в конфигурациях. Запрещены хардкод пользовательских текстов и скрытые production fallback-значения баланса в C#. Технические алгоритмы, инварианты, перечисления и протокольные ID допустимы.
- Мапперы Authoring преобразуют и валидируют ScriptableObject в неизменяемые чистые C# definitions. Передавай их через DI. Runtime-состояние и настройки игрока храни отдельно от ScriptableObject. Domain остаётся независимым от Unity.
- Используй стабильные ID. Версионируй отдельно сохранения, правила, баланс, контент и алгоритм RNG. После реализации соответствующего валидатора критические ошибки конфигурации блокируют сборку. [Конфигурации](docs/technical/configuration-system.md) · [Локализация](docs/technical/localization.md)
- В T01 ограничь Authoring шестью типами TD-014. В Release игроку доступен только профиль Production. Добавляй конфигурации будущих систем по мере реализации механик. [Объём T01](docs/technical/configuration-system.md)
