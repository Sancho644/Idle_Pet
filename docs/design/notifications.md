# Notification System — предложение

Статус: предложение до отдельного утверждения. Исследование Windows Toast запланировано на T04. Цель — напоминать об уходе при закрытой игре, сохраняя правила GD-003.

Android: Unity Mobile Notifications, локальное планирование; не требуется сервер/FCM для MVP. Windows: системные Toast, нативный адаптер; отдельно проверить запланированные уведомления при закрытом приложении, AUMID/регистрацию и запуск по нажатию в обычной неупакованной сборке. Резервный вариант — вспомогательный процесс/Task Scheduler после согласования. Editor — тестовый provider.

События: голод, скука, гигиена, сон, болезнь, критическое здоровье, вылупление, взросление, эволюция. Уровни — информационный, предупреждающий, критический. Пороги и категории настраиваемые. Общий выключатель, категории, опциональные тихие часы; отключение уведомлений не останавливает симуляцию.

NotificationPlanner прогнозирует события на глубокой копии состояния и RNG тем же ядром, что online/offline. Планирование не создаёт фактических игровых событий. Прогнозный горизонт ограничивает только уведомления, не жизнь питомца. Стабильные ID по поколению и событию, дедупликация, отмена устаревших уведомлений и пересчёт после изменений/перехода в фон. Не планировать события после прогнозной смерти. При возобновлении сначала отменить устаревшие уведомления, рассчитать жизнь, затем перепланировать. Не полагаться только на OnApplicationQuit.

Интерфейсы: INotificationProvider (Schedule, Show, Cancel, CancelAll, доступность), NotificationService, NotificationPlanner, NotificationSettings. Платформенные адаптеры изолированы. Уведомления best effort: разрешения, энергосбережение, выключение устройства, тихие часы и ограничения ОС могут помешать доставке. Не обещать точную доставку.

Тесты: прогноз не меняет состояние/RNG, отмена/дедупликация, выключенные разрешения, смерть/новое поколение, фон и перезапуск, реальное Android-устройство и Windows Standalone вне Editor. До подтверждения Windows spike не считать Windows Toast реализованными.
