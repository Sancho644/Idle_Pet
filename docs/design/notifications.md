# Уведомления — требования и реализация T04

SD-11 и итоговый аудит закрепляют прогноз, его изоляцию от игрового состояния и тихий ночной отдых по умолчанию. Платформенные механизмы, пакеты, конкретные типы уведомлений и способ доставки согласуются отдельно в T04. [Реестр решений](../decisions.md) · [O-11](../open-items.md)

## Утверждённое поведение

- Прогноз выполняется тем же ядром на глубокой копии `GameState` и всех потоков RNG. Он не меняет реальное состояние, курсор, RNG, сохранения и ресурсы. Проигрывание прогноза не публикует фактические события жизни питомца.
- После значимых действий и изменений состояния пересчитывать прогноз. Примеры: кормление, освещение, сон, лечение, смена поколения и расписания. Устаревшие уведомления отменяются. Уведомления дедуплицируются по стабильной идентичности поколения и события. Конкретная схема ключей и восстановления очереди открыта.
- По умолчанию системные уведомления не беспокоят игрока в его период ночного отдыха. Тихие часы, разрешения ОС, доставка и отсутствие сети не меняют течение симуляции. Горизонт прогноза ограничивает только планирование сообщений. GD-003 сохраняет весь офлайн-интервал.
- Доставка best effort. Прогноз может измениться после действия игрока или изменения условий. После прогнозной смерти новые уведомления о событиях жизни этого поколения не планируются. Случайную болезнь или смерть нельзя выдавать за гарантированный исход.

Утверждённая просьба выключить основной свет подаётся внутри игры по GD-012. Возможность вывести её как системное уведомление, другие типы сообщений, уровни важности, пороги и управление тихими часами остаются предложениями. ## Варианты реализации T04

- `NotificationPlanner`, `NotificationService`, `NotificationSettings` и `INotificationProvider` — предлагаемые контракты. При возобновлении сверить очередь, обработать офлайн-интервал и заново спланировать актуальные предупреждения. Не полагаться только на `OnApplicationQuit`. Пользовательские сообщения разрешаются через String Tables. [Локализация](../technical/localization.md)
- Android — кандидат Unity Mobile Notifications с локальным планированием. Нужно проверить разрешения, остановку процесса, фон и энергосбережение. Сервер и FCM для этого варианта не требуются.
- Windows — исследование Toast для неупакованной Steam-совместимой сборки. Проверить идентичность приложения, регистрацию, планирование при закрытой игре, отмену, активацию и удаление. Вспомогательный процесс или Task Scheduler требуют отдельного согласования. Editor provider может служить тестовой заглушкой.

Приёмка прогноза проверяет отсутствие мутаций, повторную постановку, отмену, смену поколения, тихие часы и одинаковое игровое состояние при выключенных уведомлениях. Платформенная приёмка проводится в T04 на Android-устройстве и в Windows Player после выбора адаптеров. Платформенные реализации пока не созданы и не проверены.
