# Coding standards

- Английские имена типов и API, PascalCase для типов/публичных членов, camelCase для параметров, _camelCase для приватных полей. Для сборок и пространств имён проекта использовать `IdlePet.*` по TD-001. Не переименовывать существующий код без необходимости.
- Один основной тип на файл; явные зависимости через конструктор в pure C#, сериализованные поля Unity только для представления/authoring. Избегать глобальных mutable singleton и service locator.
- Время передавать явно через логический курсор `long` в миллисекундах. Системные, платформенные часы и Unity Time остаются за границей Domain. Авторитетная случайность использует независимые сериализуемые потоки PCG32 v1 по TD-017. `UnityEngine.Random` и `System.Random` для неё запрещены.
- Границы состояния проверяются в домене. Не применять эффекты дважды из анимаций и логических действий. Не скрывать исключения пустым catch.
- Тесты Arrange/Act/Assert; fake clock и фиксированный RNG; никаких реальных задержек для доменных тестов. Проверять длинные интервалы и разбиение на шаги. PlayMode для навигации/инпута/представления. Отчёт содержит фактически выполненные проверки.
- Не добавлять зависимости, оптимизации и абстракции без понятной задачи. Профилировать на целевых устройствах. Соблюдать платформенные asmdef-ограничения. Сохранять .meta, не коммитить Library/Temp/сборки/секреты.

## Data-Driven Architecture и No Hardcode

- Настраиваемые значения, вероятности, пороги, коэффициенты, тайминги, контент и ссылки на Unity-ресурсы определяются в ScriptableObject и каталогах. Добавление контента в рамках существующих механик выполняется через данные. Технические константы, например идентификаторы протокола, алгоритмы, перечисления и инварианты, допустимы в коде. Тестовые фикстуры отделены от Production. Скрытые production-значения запрещены.
- Config Mappers переводят Unity-авторинг в проверенные неизменяемые Domain Definitions. Внедряйте зависимости конструктором. Прямые ссылки на ScriptableObject, UnityEngine и I/O остаются за границей Domain. Runtime-состояние хранится отдельно и не записывается в исходные SO.
- Пользовательские тексты, в том числе шаблоны, хранятся в Unity Localization String Tables. Конфиги ссылаются на стабильные ключи. Domain возвращает ID, причины и значения, а Presentation форматирует числа, время и единицы. Пакет подключается по отдельному согласованию.
- Стабильные ID переживают переименование ассетов и не переиспользуются. В сохранении сериализуются данные и ID. Валидировать диапазоны, ссылки, уникальность, совместимость и локализационные ключи. После внедрения валидатора критические ошибки блокируют сборку.
- Раздельно версионировать схему сохранения, правила, баланс, контент и алгоритм RNG. Логический курсор, якоря времени, прогресс, остатки, RNG и состояние ресурсов должны относиться к одному согласованному снимку. Политика миграций определяется до T03.
- Основные характеристики хранить в каноническом fixed-point по TD-015. Ограничение и пороги проверять по полному числителю, остаток сохранять при смене скорости. Проверять переполнение. Округлять итоговую скорость один раз, половины от нуля. `float` и `double` находятся вне авторитетной арифметики потребностей.
- Соблюдать границы `AdvanceTo` и причинную очередь по TD-011–TD-012 и TD-016. Эффекты и списания привязывать к логическому действию. При отказе команды сохранять естественные события до команды, при ошибке ядра восстанавливать обработку из согласованного checkpoint.
